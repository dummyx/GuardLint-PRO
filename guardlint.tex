\title{GuardLint: Static Analysis of CRuby\\
for Checking GC Guards}

\affiliate{ISCT}{Institute of Science Tokyo,
Meguro, Tokyo 152--8550, Japan}

\author{Zhijie Xie}{ISCT}[xie@prg.is.titech.ac.jp]
\author{Hidehiko Masuhara}{ISCT}[masuhara@acm.org]
\author{Koichi Sasada}{STORES}[ko1@atdot.net]

\begin{abstract}
The reference implementation of Ruby (CRuby) requires developers of the interpreter and its C extensions to explicitly call the garbage-collection guard macro \texttt{RB\_GC\_GUARD} when needed to prevent accidental memory reclamation. Omitting this guard can cause interpreter crashes or data corruption. Adding excessive guards can impact runtime performance. In practice, many omissions have been discovered in CRuby.

This paper presents GuardLint, a static analyzer designed to detect omissions of \texttt{RB\_GC\_GUARD}. It is implemented as CodeQL queries and applied to CRuby's codebase. On CRuby 3.4.5, GuardLint marks 36 existing guards as necessary under our model, reports 265 potentially redundant guards, and flags 232 candidate omissions. Careful reviews of the results confirmed one highly likely omission; other reports illustrate both brittle patterns and model-driven false positives.
\end{abstract}
